# Audio Fixer

使用 Flutter 构建的 Android 与 Windows 音频资料整理工具。用于检查音频标签、自动检索元数据、封面与歌词，聚合为建议后安全保存回原音频，也可导出带有新标签的副本。当前版本 0.6.0。原文件保存先取得 Android 授权，写入前制作恢复备份，再写入并回读校验。

## Windows 便携版

支持 Windows 10/11 x64，完整解压 ZIP 后运行 `audio_fixer.exe`，必须保留同目录的 DLL 与 `data`。不需要安装或管理员权限；当前构建未代码签名。

Windows 版使用文件夹音乐库：默认只读浏览用户 Music 文件夹；点击右上角文件夹按钮添加目录后，可扫描其子目录并保存已审核的原文件。不会自动扫描整块磁盘，不跟随文件链接/目录重定向。元数据、封面、歌词的自动检索、逐字段审核、批量处理、试听、纯音乐标记、TXT 清单和安全标签写回共用现有流程。导出时选择目标文件夹并生成新文件，不覆盖已有同名文件。

原文件保存会先验证已审核的临时副本，核对原文件摘要，保留原始备份与恢复记录，再替换并回读；未解决的恢复事项会阻止后续写入。媒体文件仍留在用户所选位置，设置、目录缓存和备份放在当前用户应用支持目录。

试听由 Windows Media Foundation 提供，格式支持取决于系统解码器与媒体组件。Windows 仍可获取来源已有中文译文，暂不提供 Android ML Kit 本机机器翻译。

在配置了 Visual Studio C++ 桌面开发工具的 Windows 上构建：

```powershell
flutter pub get --enforce-lockfile
flutter test integration_test/windows_runtime_test.dart -d windows
flutter build windows --release
```

Windows 云端流程见 `.github/workflows/windows.yml`：运行平台集成测试、构建优化 x64 EXE、打包微软运行库、验证真实 EXE 创建窗口，并压缩完整目录及 SHA-256 清单。不创建 Release 或自动合并。该测试不替代用户电脑上所有音频格式与驱动的兼容性验证。

## 已实现

- 默认读取 Android MediaStore 系统音乐库，授权后自动显示歌曲，无需手选导入。
- Android 13+ 请求 `READ_MEDIA_AUDIO`，旧版使用 `READ_EXTERNAL_STORAGE`；拒绝后显示授权入口，永久拒绝时引导系统设置。
- 进入应用、返回前台和点击刷新时同步系统索引中的歌曲；列表以 content URI 标识原文件，不复制整库音频。
- 初始列表按可见行异步读取各音频自身的内嵌封面缩略图，无需先进入详情。读取并发、缩略图尺寸和内存缓存均有上限，滚出屏幕的排队请求会取消；刷新后重新校验，无封面或无法读取时显示占位图。此过程不查询网络，也不会把歌曲误标为已完整检查。
- 打开详情时按需读取临时副本，读取结束后清理；文件变化后重新检查标签。
- 在独立 isolate 读取已有歌名、歌手、专辑、年份、时长、内嵌歌词和封面。
- 音乐库、搜索、待补全/读取异常筛选、歌曲详情。
- 歌曲详情以「自动检索并修复」为主入口，直接使用已有标签和解析后的文件名检索，不要求先填写表单。找到结果后直接进入原值与候选值对比；手动编辑和调整检索条件位于折叠的备选入口。可逐项检查和修改歌名、歌手、专辑、专辑歌手、年份、流派、音轨序号/总数、碟片序号/总数、作曲、备注、歌词与封面；可修正已有错误值。手动输入只生成未确认草稿，审核页显示原值与新值，未选字段保持不变。
- 支持通过系统文件选择器选择本地 JPEG/PNG 封面，私有副本以内容摘要保存；限制 10 MiB、1600 万像素和边长 8192，并验证图片可解码。取消选择不改变原图；本地封面需明确选择，可靠的缺失封面可加入建议；点击应用后才会写入。
- 自动检索会请求全部已接入来源支持的字段，包括已有错误值，不受缺失项开关影响；来源无资料或版本无法确认时保留原值。需要时可在次级「调整检索条件」中选择字段并单独调整检索用的歌名、歌手和专辑。网易云音乐实验性来源也提供经同一歌曲 ID 复核的歌名、歌手、专辑和封面候选，不再只有歌词。某个独立接口失败时保留已核对结果，并明确显示警告。
- 缺少歌手时，先按歌名与时长查找可能的歌曲版本，显示歌手、专辑、时长差与来源，由用户明确选择。不会擅自选时长最近的一版；选择后只取同一来源歌曲 ID 的元数据、封面和歌词，仍须逐字段审核才能保存。版本选择可持久恢复，当前结果重试和翻译保持所选 ID；资料已变化时重新查找。实现与公开验证见 [仅凭歌名查找版本](docs/TITLE_ONLY_SEARCH.md)。
- 严格匹配没有可用资料时，仅对正常返回未匹配的录音发现来源做一次有界版本查找，仍核对已有歌手；可从「仅凭歌名查找版本」明确忽略不确定的歌手标签，再人工确认身份。失败来源不会因此立即重复请求。
- 检索前保守识别文件名或标签歌名中的明确音质、码率、来源后缀以及歌手片段；查询页显示推导说明，已知歌手完整出现在名称末尾时，可将其分离为检索线索，不凭最后几个词猜歌手。原始文件名和标签不会自动改变。Live、Remix、伴奏、重制版等版本区别及不明括号内容保留，可手动校正检索线索。
- 设置中的「导出音频清单 TXT」独立遍历已获授权的系统音频索引，包含音乐库排除的文件夹、短音频和非音乐分类条目。逐首读取可用资料，显示进度并允许停止，通过系统窗口选择保存位置；清单区分索引信息与实际读取标签、记录读取失败及覆盖限制。不附音频、完整歌词或封面图片，也不自动上传或分享。
- 列表每行提供独立的试听按钮，多选时也可直接播放；勾选歌曲不会自动播放。底部简易播放器显示当前歌名、播放进度与时长，可暂停、继续、拖动进度和关闭。切换歌曲会释放上一首，离开音乐库、切到后台、失去音频焦点或断开耳机时停止或暂停，不提供后台播放。
- 试听直接读取本地 MediaStore 音频或已有应用私有副本，不联网、不申请新的权限。保存、导出与恢复前先等待播放器释放，并在处理期间禁止重新播放；停止无法确认时不开始写入。实际可播放格式取决于 Android 解码器，权限不足、损坏或不支持的音频会显示可重试提示。
- 补全任务入口、各项目开关、任务状态和候选信息模型。
- MusicBrainz 元数据、LRCLIB 歌词、网易云音乐（实验性）元数据/封面/歌词、Cover Art Archive 封面在线查询；候选带来源和匹配依据。网易经核对的歌曲详情可提供专辑歌手、发行年份与音轨序号；MusicBrainz 按录音/作品/发行版本查询流派、作曲与序号/总数等扩展标签，同专辑版本有分歧时不猜填。覆盖与验证限制见 [MusicBrainz 扩展资料](docs/musicbrainz-metadata.md) 和 [网易扩展资料](docs/NETEASE_EXTENDED_METADATA_VERIFICATION.md)。
- 外语歌词默认附加来源已有的中文译文，设置与候选页均可关闭；原文与译文分开预览并按原始时间戳合并。没有译文时明确提示，不伪造翻译。首次同意本机翻译的数据说明并通过 Wi-Fi 下载所需模型后，没有来源译文时可由 Google Translate / ML Kit 在设备上补充机器译文；歌词不上传，机器译文会单独标注并仍需确认。
- 相同请求合并、应用私有响应缓存及跨重启冷却；按来源排队限速，429/503 遵守 Retry-After，不进行自动重试风暴。
- 检索结果逐来源区分未匹配、超时、网络错误、服务器错误和真实限流；保留原始失败原因与绝对重试时间。动态倒计时只更新界面，所有可查询来源仍在冷却时禁止重复提交；部分来源不可用时仍可使用其他来源的候选和精确查询缓存。详情按需展开，不再把全部字段混成一个错误列表。实现与公开验证见 [检索诊断与恢复](docs/QUERY_RECOVERY.md)。
- 歌词/封面预览、逐首保存任务、失败重查、设置中的数据源连接测试。
- 歌词未检索到时可手动「设为纯音乐」，也可随时取消。标记在本应用持久保存，跳过后续歌词查询及翻译，不再将歌词计为缺失，仍可补齐其他资料。未找到歌词不会自动判为纯音乐；标记不改写音频标签、已有歌词或封面，也不会写入假的「纯音乐」歌词。
- 多选与筛选结果选择、批量查询和批量保存；候选必须逐字段审核，只有已经明确批准的项目才能进入批量写入。
- 音乐库及补全任务的多选工具栏固定在列表底部；滚动长列表时仍可全选、清空、查询所选、保存原文件及从更多菜单导出副本。搜索或分类变化会移除隐藏选择，避免误操作。
- 可持久保存按存储卷区分的文件夹排除规则（包含子文件夹），以及严格小于 60 秒的音频排除规则；60 秒边界保留，时长或文件夹未知时明确提示并暂时保留。排除不删除文件、目录记录或恢复备份。刷新和批量失败重试均重新应用规则，恢复显示不会自动重新选中。
- 批次逐首记录排队、执行、待审核、原文件已保存、副本已导出、跳过、取消和失败；停止只阻止后续项目，当前文件完成安全处理后停止。
- MP3、FLAC、M4A/MP4 先在临时副本写入并校验所选标签、已有常用标签、封面和编码音频摘要。只有明确审核的替换项能改写已有值；检查原值与封面摘要，保留未知/私有标签、未选常见字段及其他图片。数字序号修改保留未选的总数；不明、重复或暂不支持的结构会停止写入。之后选择「保存到原文件」或「导出副本」。原文件保存经系统授权，保留可恢复备份，并回读核对完整文件摘要。
- 分离「待检查」「待补全」「读取异常」状态；刷新失败保留上次列表并显示重试提示；搜索歌名、歌手、专辑和文件名。
- 本地 JSON 持久化、中文界面、深浅主题、手机导航栏与宽屏导航轨。

自动检索能力和单首歌曲有多少资料是两回事：来源返回且录音/专辑版本能核实时才出现候选；没有可靠值时保留原资料。备注为用户自定义文字，不从在线来源猜测。

标签能否读取取决于实际文件格式和标签编码。未检查的文件不会误报为缺失；读取失败会显示「读取异常」。系统索引为空、权限未授权和查询失败分别呈现，应用不会填充演示歌曲。

当前按需标签读取的单文件上限为 512 MiB，超限会明确提示；歌曲仍可出现在系统音乐库列表中。常见可编辑字段不代表支持任意自定义 tag；未选和未知标签尽量按原始字节保留，不提供自动清空全部标签。空白输入不删除已有内容。

清单导出使用 Android 系统媒体读取器，不能保证读到所有格式的扩展标签；缺失、未检查与读取失败分别标注。未被 MediaStore 索引的文件、未授权位置和其他应用的私有音频不在覆盖范围内；它不会申请全盘文件管理权限。

## 功能范围

在线查询已接入 MusicBrainz、LRCLIB、Cover Art Archive，以及无需登录的网易云音乐公开只读端点（实验性、非官方稳定 API）。当前功能无需配置 API Key。网易端点可用性和授权范围不受本项目保证，拒绝访问时直接报告错误，不尝试登录、代理或绕过限制。详细限制见 [歌词来源与网络行为](docs/LYRICS_SOURCES.md)。可靠且无冲突的缺失项会预选，已有值或有分歧的候选默认保留；点击应用后才可保存。原文件保存是显式操作，不会在查询后自动执行；副本导出仍可选。尚未实现全盘扫描和系统后台调度。`CompletionService` 只查询候选，不修改音频；独立 `SafeAudioCopyExporter` 负责准备和验证标签副本，Android 桥接负责原文件授权、备份、回读和恢复，或将副本交给系统保存。第三方资料缺失、同名版本无法区分、网络错误会明确显示结果。

只在发起补全、连接测试或加载所选封面预览/导出时请求在线来源。补全会发送歌名、歌手、专辑和时长，不上传音频。MusicBrainz 和网易云音乐同来源请求完成后间隔至少 1.1 秒，其他来源至少 400 毫秒；相同请求合并和缓存，HTTP 429/503 与网易响应码的冷却会限制后续请求并跨重启保留。短时故障可以稍后重试，停止批量任务会等待当前歌曲处理结束并保留已完成结果。

只显示系统媒体索引中标记为音乐的非空音频，未被系统识别、处于回收站或其他应用私有目录中的文件不在列表内。应用只在审核候选并明确保存后修改所选原文件，不删除音乐，也不申请全盘访问权限。音乐索引和封面缓存在应用内；旧版本已导入的私有副本保留，原导入流的 `Uint8List` 类型错误已修复并有回归测试。

## 运行

本项目由 Flutter 3.47.2 / Dart 3.13.2 生成。使用匹配的 Flutter SDK 和 Android SDK。

```powershell
flutter pub get
flutter devices
flutter run -d <安卓设备ID>
```

构建调试 APK：

```powershell
flutter build apk --debug
```

用于独立安装验证的优化 ARM64 QA 包（Linux/macOS shell）：

```sh
ORG_GRADLE_PROJECT_audioFixerQa=true flutter build apk --release --split-per-abi --target-platform android-arm64
```

产物为 `build/app/outputs/flutter-apk/app-arm64-v8a-release.apk`。QA 开关适用于所有构建模式，使用独立包名 `com.audiofixer.audio_fixer.qa.v030`、显示名 `Audio Fixer QA 0.6` 和 `-qa` 版本后缀，可与正常应用及旧版 QA 并存。0.3 QA 使用独立应用数据，旧 QA 的私有副本与任务记录不会迁移或删除；系统音乐库仍需重新授权。无需卸载旧 QA。未设置开关时保留原包名与名称。

这是 AOT 优化、测试签名的 QA 包，不是正式发布签名。签名不同的 APK 无法覆盖更新旧版；不要为绕过签名冲突而直接卸载旧应用，以免丢失本地目录/私有副本。自动质量流程见 [CI 说明](docs/CI.md)。

产物：`build/app/outputs/flutter-apk/app-debug.apk`。Android 宿主使用 Kotlin，包名暂为 `com.audiofixer.audio_fixer`。发布前应确认包名并配置正式签名；模板中的 release 签名仍为调试签名。

Windows 本地构建中遇到项目与 Pub 缓存分处不同盘符的 Kotlin 增量缓存错误，因此项目的 `android/gradle.properties` 设置了 `kotlin.incremental=false`。此项只影响 Kotlin 构建性能；同盘开发环境可在验证后移除。配置说明见 [Kotlin 官方文档](https://kotlinlang.org/docs/gradle-compilation-and-caches.html#incremental-compilation)。

## 结构

```text
lib/
  main.dart                      依赖装配与入口
  app/                           主题、中文本地化、主导航
  core/
    models/                      音频、设置、补全任务及候选模型
    services/
      device_music_library.dart  Android 系统音乐库、权限与按需文件读取
      audio_tag_reader.dart      独立 isolate 标签/歌词/封面解析
      audio_importer.dart        兼容旧导入服务与私有副本清理
      export/                    安全标签准备、音频摘要校验、原文件/副本保存
      metadata_source.dart       在线数据源适配接口
      completion_service.dart    根据开关查询缺失项，生成候选预览
      sources/                   三个在线适配器、HTTPS 请求、限流和匹配
    storage/library_store.dart   本地目录及设置持久化
  features/
    library/                     状态控制、音乐库、歌曲详情
    tasks/                       最近一次补全结果
    settings/                    补全内容、主题、数据源状态
  shared/                        公共组件与格式化
android/app/src/main/kotlin/      MediaStore、权限和 content URI 读取桥接
test/                            音乐库、权限、文件流、持久化和界面测试
```

状态管理使用 Flutter 自带 `ChangeNotifier`。系统音乐库、存储和数据源通过构造参数注入，后续可单独替换。UI 不直接读写文件或发起在线搜索。Android 接入方式依据 [官方媒体存储文档](https://developer.android.com/training/data-storage/shared/media) 和 [Android 13 音频权限说明](https://developer.android.com/about/versions/13/behavior-changes-13#granular-media-permissions)。

## 扩展在线补全服务

1. 实现 `MetadataSource`，声明 `name`、`supportedFields` 和 `lookup`。可为元数据、歌词、封面分别提供适配器。
2. 在 `sources/online_sources.dart` 的 `createOnlineSources` 中注册适配器。元数据和封面共用 `MusicBrainzCatalog`，避免同一歌曲重复检索。
3. 每条 `FieldSuggestion` 保留字段、候选值、来源链接和匹配说明。缺失项补全只传入缺失字段；显式自动修复可查询已有字段，但结果仍须逐项审核替换。HTTP 请求的超时为 12 秒，每个完整来源流程上限 45 秒。单个来源失败不会丢弃其他来源的候选，任务会同时说明失败来源。
4. 建议经 `CandidateReviewPage` 查看并应用后交给独立 `SafeAudioCopyExporter`，先生成并验证临时副本，再由原生层安全保存回原文件或导出。新格式必须增加标签回读、编码音频摘要和独立解码测试，再加入支持列表。不要在查询适配器里修改音频。
5. Android 主清单已声明 INTERNET。HTTP 客户端只访问当前服务及 archive.org 的允许列表 HTTPS 地址；新增服务需明确加入地址允许列表。公开发布前应为 User-Agent 配置实际项目联系地址。

当前批处理按顺序执行并逐首保存，任务和批次状态写入本地存储；只保留每首歌曲最近一次候选任务。系统后台执行与进程终止后自动续跑尚未实现，重启会将中断项目标明而非自动重写。未命中不会填入占位资料，候选存在不会标为已经写入文件；只有原文件保存并回读成功才更新其检查状态。导出成功独立显示「已导出副本」，不把原文件的缺失状态改成完整。

接口依据：[MusicBrainz API](https://musicbrainz.org/doc/MusicBrainz_API)、[MusicBrainz 限流说明](https://musicbrainz.org/doc/MusicBrainz_API/Rate_Limiting)、[LRCLIB API](https://lrclib.net/docs)、[Cover Art Archive API](https://musicbrainz.org/doc/Cover_Art_Archive/API)。

## 原文件保存、批量处理与限制

1. 选择一首或多首歌曲，检查标签并自动检索可用资料。批量默认完整修复，可明确切换为仅补缺失；查询按顺序执行。批量查询前确认数量、查询内容和联网范围。
2. 在「确认候选资料」查看值、来源和匹配依据，明确勾选允许写入的字段。候选不会默认视为批准，未审核歌曲不能混入批量写入。
3. 选择「保存到原文件」或可选的「导出副本」。两者先在私有临时目录生成新标签文件；已有字段仅在显式修复任务中，审核并批准该替换候选后才允许更新。
4. 校验所选标签、未修改的常用标签、封面及 MP3 编码数据、FLAC STREAMINFO/音频帧、MP4 编码数据/解码所需采样表的摘要。校验不通过不进入保存步骤。
5. 原文件保存：取得 Android 对该文件的写入许可，在写入前保存原始字节和持久恢复记录，并再次核对原文件与本次生成已校验写入文件时的完整摘要。授权取消不写入。写入后回读核对完整文件摘要；同一次保存中的写入或验证失败会尝试回滚本次写入。恢复不成功会保留记录并明确提示，不将歌曲标为成功。进程重启后遇到既非原始摘要、也非预期结果摘要的文件，会保留当前文件与备份并等待明确选择，不自动覆盖。
6. 导出副本：单首使用系统「创建文档」弹窗，批量先选一个目标目录，再逐首创建独立新文件；保存后校验文件摘要。取消或失败不会把副本当作原文件修复成功。提供程序不支持清理时，需要检查可能残留的不完整副本。
7. 查看逐首结果和真实计数。可停止后续处理；当前歌曲的写入/校验/恢复会先完成。失败项目可以重试，不重复处理已成功项目。

- 原文件保存及副本导出仅支持 MP3、FLAC、M4A/MP4；原文件保存只针对系统音乐库的 MediaStore 文件。旧版导入的应用私有副本以内容摘要标识，为避免破坏去重身份，只能导出新副本；这不影响系统音乐库原文件保存。WAV、OGG 等可读格式仍供检查与预览，不声称已修复。
- 单文件上限 512 MiB；封面仅接受可信来源的 HTTPS JPEG/PNG，最大 10 MiB。来源地址和每次跳转均需校验。
- Android 11+ 使用 MediaStore 写入授权，批量只为已确认且支持的歌曲集中申请，并复用当前 Activity 的写入许可（每组至多 1000 首）；Android 10 遵循可恢复写入权限流程；较旧系统依照文件写权限处理。设备、Android 版本和存储提供程序可能拒绝访问，此时明确失败或取消，不静默改用副本替代。
- 系统索引或已读取关键资料发生变化、待写字段已有内容或解析器无法校验时停止保存；准备写入后还会比对完整文件摘要。重新读取与重新查询后再审核；歌曲详情允许强制重新读取，即使系统索引尚未更新。
- 原文件备份用于写入失败及进程中断恢复，不是长期版本历史，也不是每次成功保存的撤销功能。重启后的未知版本不会自动覆盖；恢复面板可检查保留版本、导出副本和明确恢复原始备份。重新授权只重新检查，不等于同意覆盖。明确恢复前还会另存当前版本，未安全保留或导出的不同版本不能被清理。清除应用数据或卸载可能删除这些私有备份，恢复未完成时不要这么做。
- 普通保存通过校验且任务记录确认后清理临时备份；冲突恢复必须满足版本保留条件并明确完成后才清理。源文件与任务/批次记录均需如实反映结果；中断不自动重复批量写入。
- 复杂 ID3、分片/外部引用/非音频 MP4 等无法可靠校验的结构会安全拒绝。MP4 追加 moov 以保留媒体绝对偏移，输出可能变大并失去 fast-start 优化。
- 不承诺修复损坏音频、转码、自动纠正乱码或支持所有播放器私有标签；重要音乐建议另有备份，并在常用播放器验收。
- 副本出现在系统音乐库的时间取决于保存位置与设备媒体索引，不自动替换原列表记录。批量任务不是系统后台任务，应用被终止后不自动续跑。

## 离线真实音频验证

工具会自行合成短测试音，不需要下载或分发商业音乐。安装 Python 3、FFmpeg 后运行：

```sh
python3 tool/generate_audio_fixtures.py
flutter test test/audio_fixture_test.dart --reporter expanded
```

覆盖 MP3/FLAC/M4A/WAV/OGG/Opus/AIFF、中文/日文/组合字符、无标签、封面、重复、伪装扩展名、截断/损坏与不支持的格式。导出测试以独立 FFmpeg 全量解码及编码包 SHA-256 检查前后音频一致，另用 ffprobe 核对已有标签。

可选地设置 `AUDIO_FIXER_REAL_INPUTS` 为本机测试歌曲目录，执行相同的离线副本验证。仅将自行编写的测试歌词填入缺失项；不会请求在线来源。输入歌曲和报告保存在忽略的 `build/test_samples/` 或调用者目录，不能加入版本库。

```sh
AUDIO_FIXER_REAL_INPUTS=/path/to/local/audio flutter test test/audio_fixture_test.dart --reporter expanded
python3 tool/validate_audio.py compare original.mp3 exported.mp3
```
